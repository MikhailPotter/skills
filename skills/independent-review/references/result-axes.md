# Result review axes

Select checks using the caller's scope and completion policy. For a general result review, include all applicable axes within that scope. Collect automatic evidence once when it covers multiple criteria and map it to each criterion. Reserve separate reviewer assignments for judgment.

| Axis | When applicable | Evidence and assignment |
|---|---|---|
| **Acceptance and behavior** | A task or result is assessed against expected behavior, criteria or claims. Include the integrated outcome for a whole topic. | A fresh reviewer derives cases from the brief, checks expected and actual outcomes, and looks for missing, incorrect and extra behavior. For non-code work, assess the evidence behind the claims. Cite the criterion, scope or decision. |
| **Solution quality** | A consequential design choice or feasibility assumption affects the outcome, compatibility or constraints. | A fresh reviewer compares the choice with constraints and alternatives. Use a prototype or experiment when an assumption needs validation. Review can inform the approach early. Repeat it if the implemented approach changes materially. |
| **Implementation quality** | Code or another executable artifact changes. | A fresh reviewer inspects the exact change and relevant surrounding behavior for defects, regressions, failure handling, maintainability and the usefulness of checks. |
| **Project rules** | Documented project rules apply. | Run enforced checks such as lint, types and architecture checks through project tools. Assign documented rules requiring judgment or missing tool coverage to a separate fresh reviewer. |
| **Efficiency** | Efficiency is a criterion, an improvement is claimed or the change materially affects resource use. | A fresh reviewer evaluates measurements, workload and method and independently checks material claims where possible. Compare equivalent conditions with a baseline for improvements or with a target for a stated requirement. Record limits. |
